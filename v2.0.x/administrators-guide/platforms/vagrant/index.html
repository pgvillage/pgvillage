    Vagrant¶

    Run a PgVillage demo environment on your laptop with Vagrant and VirtualBox. Everything you need is in this repository:

    • vagrant/: the Vagrantfile and the scripts that prepare the boxes.
    • inventories/standard: the standard PgVillage config, shared by all platforms. It is multi-instance: two stolon clusters (cluster1 and cluster2) run side by side on the same hosts.
    • inventories/ubuntu, inventories/el or inventories/suse: the OS of the boxes (Ubuntu by default). See Ubuntu, EL and SUSE.
    • inventories/vagrant: everything specific to the vagrant boxes: the hosts, the network, certificates, and the router (HAProxy, keepalived and pgroute66). See The vagrant inventory.

    What gets deployed¶

    Host IP Groups Runs
    ansible.local 172.30.1.10 localhosts (as localhost) Ansible, chainsmith; you deploy from here
    db-1.local 172.30.1.31 hacluster, stolon, etcd_master, router etcd, and per cluster: stolon (sentinel, keeper, proxy), PostgreSQL, PgBouncer, wal-g, avchecker; plus HAProxy, keepalived and pgroute66
    db-2.local 172.30.1.32 same same
    db-3.local 172.30.1.33 same same
    minio.local 172.30.1.20 backup minio (RustFS on Ubuntu), with a bucket per cluster
    VIP 172.30.1.30 keepalived VIP for HAProxy

    The ports per cluster:

    Cluster PostgreSQL stolon proxy PgBouncer HAProxy on the VIP (rw / ro / proxy)
    cluster1 5433 25433 6433 35433 / 45433 / 55433
    cluster2 5434 25434 6434 35434 / 45434 / 55434

    See Router.

    The database hosts get 2 GB of memory, the others 1 GB, all 2 CPUs: about 9 GB for the whole environment.

    Getting started¶

    1. Install VirtualBox and Vagrant.
    2. Create the box, once: see Creating the boxes.
    3. Start the boxes: 
      cd vagrant
vagrant up
      This creates the five boxes, gives them a static IP on the private network, seeds /etc/hosts, shares one ssh key between them, and creates the data and wal directories on the database hosts. On the Ansible host it installs Ansible and the roles and collections from requirements.yml.
    4. Log in to the Ansible host and deploy: 
      vagrant ssh ansible
cd ~/git/pgvillage/
ansible-playbook -i inventories/standard -i inventories/${PGV_OS:?} -i inventories/vagrant functional-all.yml
    5. Be amazed.

    ~/git/pgvillage on the Ansible host is this repository on your laptop (a VirtualBox shared folder), so you deploy what you have checked out, including your local changes. PGV_OS is set in ~/.bashrc of the Ansible host (see Other operating systems).

    Check the deployment¶

    vagrant ssh db-1
sudo -u postgres psql -h /tmp -p 5433 -Atc 'select pg_is_in_recovery()'   # cluster1
sudo -u postgres psql -h /tmp -p 5434 -Atc 'select pg_is_in_recovery()'   # cluster2

    One host returns f (the primary of that cluster), the others t (standbys). The primaries of cluster1 and cluster2 don't have to be on the same host. sudo -iu postgres (a login shell) also shows the stolon status of both clusters.

    Through HAProxy on the VIP (read-write goes to the primary, read-only to a standby):

    sudo -iu postgres psql "host=172.30.1.30 port=35433 dbname=postgres sslmode=require" -Atc 'select inet_server_addr(), pg_is_in_recovery()'
sudo -iu postgres psql "host=172.30.1.30 port=45433 dbname=postgres sslmode=require" -Atc 'select inet_server_addr(), pg_is_in_recovery()'

    Other operating systems¶

    The boxes run Ubuntu by default. PGV_OS picks another OS; it selects the box and is the name of the OS inventory to deploy with:

    PGV_OS Box OS inventory
    ubuntu (default) nibble/ubuntu-26.04 inventories/ubuntu
    el nibble/rocky-9 inventories/el
    suse nibble/suse-16 inventories/suse 
    cd vagrant
PGV_OS=el vagrant up

    Set it for every vagrant command on these boxes (vagrant up, vagrant provision, vagrant destroy), e.g. with export PGV_OS=el. PGV_BOX overrides the box name, if you named your box differently.

    The bootstrap writes PGV_OS to ~/.bashrc of the Ansible host, so the deploy command in Getting started uses the right OS inventory.

    Note

    The PostgreSQL community (PGDG) has no aarch64 packages for SUSE: on Apple silicon, use ubuntu or el, or SUSE with PostgreSQL packages from another source. See SUSE.

    The vagrant directory¶

    File What
    Vagrantfile The boxes: ansible, minio and db-1 to db-3, all on the private network 172.30.1.0/24
    scripts/init_vm.sh All boxes: new ssh host keys, the shared ssh key, /etc/hosts, chrony steps the clock after a suspend
    scripts/set_ip.sh All boxes: the static IP on the private network (with NetworkManager, netplan or wicked)
    scripts/bootstrap.sh Ansible host: Ansible in ~/venv, the roles and collections from requirements.yml, ssh to localhost

    vagrant up creates vagrant/.ssh (the shared ssh key) and vagrant/.vagrant; both are in .gitignore.

    Mac M1+ users¶

    Apple silicon (M1, M2, M3, etc.) is no issue: create aarch64 boxes on the Mac, see Creating the boxes. VirtualBox on Apple silicon only runs aarch64 VMs, so amd64 boxes don't run there. See also macOS.

    On the Rocky Linux boxes, VirtualBox reports CPU features to the kernel that the CPU can't run, and Ansible crashes with Illegal instruction. scripts/bootstrap.sh works around it with OPENSSL_armcap=0 in ~/.bashrc (also kept for sudo). Set it yourself when you run ansible-playbook from a shell that doesn't read ~/.bashrc. See ARM vs AMD.

    DNS¶

    There is no DNS: scripts/init_vm.sh seeds the hosts into /etc/hosts of every box.

    Starting over¶

    cd vagrant
vagrant destroy -f
vagrant up

    To keep the boxes and only remove PgVillage, run uninstall.yml with the same inventories as the deploy.
